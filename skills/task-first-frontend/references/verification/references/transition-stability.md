# 전이 중 유지 조건

이 문서는 화면이 로딩·재조회·오류·선택 변경·사이드바 열림 같은 상태 전이를 거치는 동안 무엇이 그대로 남아야 하고 무엇이 사라져야 하는지 정하고 검사할 때 쓴다. 대상은 배치, 선택, 입력, 포커스, 스크롤, 글자 표시다. 늦은 응답이 화면을 덮어쓰는 경쟁의 원인은 [클라이언트 실행 결함 리뷰](client-runtime-review.md)의 UI-02와 [행동 흐름 테스트 설계](behavior-flow-tests.md)가 맡고, 상태별 안내 문구와 다음 행동은 [상태별 안내와 다음 행동](state-design.md)이, 처리 중·실패·복구의 브라우저 증거 판정은 [브라우저 증거와 판정](browser-evidence.md)이 맡는다.

## 1. 필요성 판단: 무엇을 이해하거나 검증해야 하는가?

### 상태와 전이 파악: 무엇이 언제 달라지는가?

변경 대상에서 실제로 일어나는 사용자 행동과 비동기 사건을 확인한다. 초기 로딩, 데이터 표시, 빈 결과, 오류, 재조회, 선택 변경처럼 화면에 영향을 주는 상태를 식별하고 각 상태로 들어가거나 벗어나는 조건을 정한다.

상태는 네 갈래로 나눠 소유 주체와 수명을 확인한다. 서버에서 받은 데이터는 화면에 표시할 내용과 그 내용이 속한 조회 대상을 정하고, 요청 상태는 로딩·재조회·오류처럼 데이터 확보 과정의 진행을 나타낸다. 사용자의 선택과 입력은 현재 작업 맥락이고, 화면 표시 상태는 사이드바 열림·탭 선택·모달 표시처럼 인터페이스 구성을 정한다. 이 상태들은 한 화면에 동시에 있을 수 있다. 재조회가 시작되어도 이전 데이터와 선택은 유지될 수 있고, 오류가 나도 작성 중이던 입력은 남아야 할 수 있으므로 실제 요구사항에서 상태별 책임과 초기화 시점을 확인한다. 서로 독립적으로 변하는 상태를 한 값으로 묶어 불필요한 초기화를 일으키지 않는다.

조회 대상이 바뀌면 새 데이터가 이전 대상의 화면에 섞이지 않아야 하고, 선택이 사라졌거나 더 이상 유효하지 않으면 정의된 방식으로 처리한다. 변경과 관계없는 상태까지 나열하지 않으며, 전이의 누락이나 충돌을 확인해야 할 때만 상태 전이 표나 상태 머신을 쓴다.

### 유지 조건 정의: 무엇이 바뀌고, 무엇이 남고, 무엇이 사라지는가?

각 전이에서 바뀌어야 할 영역, 남아야 할 영역, 사라져야 할 것을 구분한다.

| 전이에서 확인할 대상 | 확인할 질문 | 검증할 수 있는 값 |
| --- | --- | --- |
| 공통 배치 | 재조회나 오류 표시 때문에 헤더, 툴바, 사이드바가 밀리는가? | 요소의 위치와 크기 |
| 콘텐츠 영역 | 로딩 표시와 실제 데이터가 교체될 때 높이가 불필요하게 급변하는가? | 컨테이너 크기, 주변 요소 위치 |
| 선택과 작업 맥락 | 데이터 갱신 뒤 사용자가 선택한 항목과 작성 중인 내용이 유지되는가? | 선택 ID, 입력값, 표시 내용 |
| 포커스 | 갱신이나 목록 재정렬 뒤 입력 초점이 예상한 곳에 남는가? | 활성 요소, 접근성 상태 |
| 스크롤 | 항목 갱신이나 상세 패널 전환으로 읽던 위치가 뜻하지 않게 바뀌는가? | 문서와 내부 스크롤 위치 |
| 사라져야 할 것 | 완료·성공 뒤에 이전 로딩 표시, 오류 안내, 이전 완료 안내, 이전 폼이 남아 있는가? | 해당 요소의 존재와 화면 노출 |
| 글자 표시 | 데이터나 폭이 바뀐 뒤 글자가 잘리거나 겹치거나 한국어가 어색하게 줄바꿈되는가? | 텍스트 영역의 넘침, 줄 수, 캡처 |
| 반응형 화면 | 화면 폭이 바뀌어도 핵심 조작이 가능하고 콘텐츠가 겹치지 않는가? | 경계, 가시성, 가로 넘침 |

이 표를 모든 화면에 일괄 적용하지 않는다. 실제 사용자 작업에서 중요한 조건을 골라 어느 전이에 적용할지 구체화한다.

글자 표시는 다음을 결함으로 본다. 잘린 글자나 아래로 내려가는 획이 잘린 경우, 큰 글자 크기나 200% 확대에서 겹치는 경우, 조사나 어미만 다음 줄로 떨어지는 경우(예: `핵심 자료 / 도`), 짧은 주어구가 서술어와 갈라지는 경우(예: `두 강은 / 끝에서 만난다`), 연결·보조 표현이 중간에서 끊기는 경우(예: `쓸 수 / 있지만`), 괄호 안 출처 문자열이 줄을 넘어 끊기는 경우다. 말줄임이나 줄바꿈은 설계된 방식이어야 한다.

### 의도된 변화 판단: 이 이동은 요구사항에 맞는가?

사용자의 명시적인 조작이나 화면 의미의 변화에 따른 이동은 허용한다. 사용자가 사이드바를 펼치면 콘텐츠 너비가 달라질 수 있고, 이때는 펼친 사이드바의 너비와 본문 배치가 설계한 범위에 드는지를 검증하며 그 과정에서 입력이나 선택이 초기화되는지는 따로 확인한다.

같은 목록을 재조회하는 동안에는 기존 결과를 유지하고 진행 상태를 따로 표시하는 편이 작업 맥락 보존에 유리할 수 있다. 보안상 즉시 숨겨야 하는 데이터나 조회 대상 자체가 바뀐 경우에는 기존 내용을 계속 보이면 안 될 수 있으므로 실제 데이터의 수명과 접근 조건에 따라 정한다.

빈 화면에서 데이터가 처음 표시될 때는 높이 변화가 필요할 수 있다. 이때는 핵심 조작부와 주변 배치가 안정적인지, 필요한 공간을 미리 확보할 수 있는지 검토한다. 긴 제목이나 이미지처럼 크기를 예측하기 어려운 콘텐츠는 줄바꿈, 최대 크기, 비율, 공간 확보 방식이 요구사항과 맞는지 확인한다.

## 2. 방법 결정: 어떤 증거를 어떤 방법으로 얻을 것인가?

### 허용 범위: 얼마나 같아야 같은 것으로 보는가?

좌표나 크기를 그대로 유지해야 하는지는 화면 구조와 상태 전이 계약으로 정한다. 픽셀 단위의 완전 일치가 필요한 영역에는 그 조건을 쓰고, 글꼴 렌더링이나 반응형 배치 때문에 작은 차이가 허용되는 영역에는 근거 있는 허용 범위를 쓴다. 모든 요소에 같은 허용 오차를 적용하지 않는다.

측정은 같은 뷰포트, 스크롤 위치, 표시 상태에서 하고, 좌표의 기준이 되는 요소나 컨테이너도 함께 확인한다. 화면 크기가 바뀌는 전이에서는 이전 좌표와의 일치 대신 새 화면 크기에서 지켜야 할 배치 규칙을 검증한다. 전이의 시작과 끝에서 위치가 같아도 중간에 이동했다가 돌아왔을 수 있으므로, 중요한 작업 영역은 전이 중에도 측정한다.

### 검증 방법 결정: 어떤 증거가 필요한가?

상태와 데이터의 정합성은 상태 전이 테스트로, 위치·크기·포커스·스크롤의 유지는 브라우저에서 실제 값을 비교해 검증한다. 주요 화면의 시각적 결과는 필요한 상태에 한해 스크린샷으로 비교하며, 비교 조건과 기준 이미지 관리는 [브라우저 증거와 판정](browser-evidence.md) 2단계의 "화면 비교"를 따른다. 응답을 제어해 요청 전, 대기 중, 완료나 실패 뒤의 상태를 확인하고, 빠른 선택 변경, 빈 데이터, 긴 콘텐츠, 화면 크기 변화는 실제 결함 가능성과 변경 범위에 따라 더한다.

테스트 기법과 예시 코드가 필요할 때만 [전이 유지 검사 방법](transition-stability-tests.md)을 읽는다.

## 3. 검증 및 활용: 무엇을 확인했고 어떤 판단에 반영할 것인가?

### 검증과 수정: 어떤 조건이 충족되었는가?

관련 전이를 실행해 기능 동작과 유지 조건을 검사한다. 실패하면 어떤 사건이 어떤 상태를 바꾸었고 어떤 요소나 사용자 상태가 영향을 받았는지 확인한 뒤, 원인을 고치고 같은 전이를 다시 검증한다. 자동화할 가치가 있는 조건은 회귀 테스트로 남기고, 변경과 무관한 화면 전체로 검증을 넓히지 않는다.

공통 배치나 상태 소유 구조를 바꾸는 작업은 관련 화면의 여러 전이를 확인한다. 단일 요소의 문구나 색상을 바꾸는 작업은 변경된 화면의 시각적 결과를 중심으로 검증할 수 있다. 비동기 데이터 흐름을 고쳤다면 오류와 조회 대상 변경을 먼저 검토한다.

결과물에는 구현하거나 고친 상태 전이, 그 전이에서 유지해야 할 조건, 실행한 검증과 결과를 반영한다. 유지 조건이 복잡하거나 이후 구현에서도 참고해야 할 때만 상태 전이 표와 검증 기준을 문서로 남긴다.

### 조건 작성 예

문서 목록에서 현재 문서를 선택한 채 새로고침하면 목록 데이터는 갱신되더라도 선택이 유효한 동안 같은 문서가 선택되어 있어야 한다. 요청 중에는 편집 툴바의 세로 위치가 유지되어야 하고, 응답이 끝난 뒤에도 사용자의 작업 영역이 임의로 접히지 않아야 하며, 재조회 표시는 사라져야 한다. 이 예는 조건을 쓰는 방식을 보여 줄 뿐이며, 실제 항목과 유지 범위는 해당 프로젝트의 코드와 요구사항으로 정한다.
