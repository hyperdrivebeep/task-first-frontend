# 근거 문헌과 적용 범위

이 문서는 묶음의 판단 기준이 어떤 문헌에서 왔고 어디까지 적용되는지 설명하거나, 기준끼리 충돌할 때 쓴다. 아래는 요약과 적용 범위이며 원문을 대체하지 않는다. 도구 기능 확인용 링크는 각 문서의 참고 문서 절에 있다.

## 1. 상태별 안내의 근거: 어떤 문헌을 어디까지 따르는가?

2026-09-21에 아래 다섯 문서의 본문을 확인했다. 링크된 모든 하위 문서까지 읽었다는 뜻은 아니다.

IBM Carbon의 Empty states(https://carbondesignsystem.com/patterns/empty-states-pattern/)는 빈 화면의 이유와 맥락에 맞는 다음 행동을 설계하고, 빈 표는 헤더와 푸터까지 대체하는 패턴을 제시한다. 실제 기능이 있는 검색·필터까지 늘 없애라는 규칙으로 넓히지 않는다. Carbon은 설정 필요 상태를 오류 관리 유형에도 넣으므로 "설정 미완료는 문헌상 절대 오류가 아니다"라고 주장하지 않는다. 중요한 것은 원인에 맞는 설명과 해결 경로다.

GOV.UK Design System의 Error message(https://design-system.service.gov.uk/components/error-message/)는 입력 검증 오류 컴포넌트의 지침이다. 사용자 답변을 보존하고 수정할 입력과 메시지를 연결하며, 자격·권한·서비스 문제를 입력 실수처럼 보이지 않는다. 이 지침을 모든 장애 안내 금지나 오류 숨기기로 해석하지 않고, 영어 표현의 세부 규칙을 한국어 문구에 기계적으로 적용하지 않는다.

Jakob Nielsen과 NN/g의 10 Usability Heuristics(https://www.nngroup.com/articles/ten-usability-heuristics/)는 상태 전달, 사용자 언어, 통제와 복구, 일관성, 오류 예방, 기억 부담 감소, 숙련도별 효율, 불필요한 정보 축소, 오류 이해와 회복, 과업 중심 도움말을 검토 관점으로 쓴다. 모든 화면에 열 가지 기능을 더하라는 구현 명세가 아니다.

NN/g의 Cognitive Walkthroughs(https://www.nngroup.com/articles/cognitive-walkthroughs/)는 낯선 사용자가 구체적인 과업을 진행하는 관점에서 행동의 필요성, 발견, 결과 예상, 피드백을 단계별로 검토한다. 전문가 검토이며 실제 사용자의 행동 증거와 같지 않다. 익숙한 단순 조작에 무거운 절차를 의무화하지 않는다.

GOV.UK Service Manual의 Using moderated usability testing(https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing)은 실제 또는 예상 사용자가 현실적인 과업을 수행하는 모습을 관찰하고, 과업에 답을 암시하거나 진행자가 경로를 가르치지 않으며, 보조기술과 이용 환경을 고려한다.

상태별 요청 계약, 불필요한 호출이 없는지의 검증, 저장된 준비 상태와 초안의 구별, 캐시와 응답 경합 검토, 대상별 조건 판단은 위 문헌의 직접 명령이 아니다. 실제 제품에서 화면과 동작의 불일치를 막으려는 이 묶음의 엔지니어링 적용이다. 필수 필드, 승인 단계, 갱신 시점, 기존 데이터 접근 정책은 해당 제품 요구사항에서 정한다.

## 2. 사용성 리뷰의 근거: Krug의 책에서 무엇을 가져왔는가?

사용성 리뷰는 Steve Krug의 책을 바탕으로 만든 독립적인 실무 리뷰 절차이며 저자의 공식 스킬이나 인증 체계가 아니다.

- [O'Reilly의 *Don't Make Me Think!: A Common Sense Approach to Web Usability, Second Edition*](https://learning.oreilly.com/library/view/dont-make-me/0321344758/): 정식 접근 권한으로 Introduction과 1~12장을 읽고 기존 절차와 대조했다. 원문은 복사하지 않고 실행 가능한 원칙만 요약했다.
- [저자의 책 소개](https://sensible.com/dont-make-me-think/): Revisited 판의 범위와 후속 판본을 확인할 때 쓴다.
- [저자가 공개한 Revisited 목차](https://sensible.com/downloads/DMMT-Revisited-TableOfContents.pdf): 모바일과 후속 판본의 주제 구성을 확인한다. 목차만으로 상세 주장이나 수치 기준을 입증하지 않는다.
- [저자가 공개한 4장 샘플](https://sensible.com/downloads/DMMT-Revisited-sample-chapter.pdf): 클릭 수보다 선택의 어려움과 불확실성을 보라는 원칙을 공개 자료로 확인한다.
- [저자의 테스트 자료 모음](https://sensible.com/download-files/): 실제 사용자 테스트를 설계할 때 최신 진행 스크립트와 관찰자 자료를 확인한다.

장별로 반영한 핵심은 다음과 같다.

- 1장: 페이지를 가능하면 자명하게, 불가하면 최소한 빠르게 설명되게 만들고 불필요한 의문을 없앤다.
- 2장: 사용자는 정독보다 훑어보기, 최적화보다 첫 번째로 그럴듯한 선택, 완전한 이해보다 시행착오로 진행한다.
- 3장: 중요도·그룹·포함 관계가 보이는 계층, 익숙한 관례, 명확한 영역, 클릭 단서, 낮은 시각 소음을 점검한다.
- 4장: 클릭 수보다 각 선택의 명확성과 진행 중 확신, 잘못 골랐을 때의 비용을 본다.
- 5장: 정보 없는 환영·자기칭찬 문구와 장황한 지침을 줄이고 자가설명형 UI를 우선한다.
- 6장: 지속 내비게이션, 페이지 이름, 현재 위치, 검색, 하위 계층과 깊은 페이지의 독립적인 길 찾기를 본다.
- 7장: 홈·랜딩 화면은 정체성, 가치, 제공 범위, 시작점과 제품에 해당하는 검색·가입·로그인 진입점을 큰 그림 안에서 설명해야 한다.
- 8장: 개인·직무 취향, 이해관계자 간 충돌, 평균 사용자 가정을 특정 사용자·과업·맥락의 관찰 가능한 질문으로 바꾸고 작은 테스트로 논쟁을 푼다.
- 9장: 포커스 그룹과 사용성 테스트를 구분하고, 작고 이른 반복 관찰을 큰 막판 연구보다 우선한다.
- 10장: 숨긴 비용·지원, 불필요한 수고, 가식적 배려가 사용자의 호의를 소진하는지 보고 정직한 도움과 복구로 신뢰를 되찾는다.
- 11장: 접근성은 사용성의 전제다. 자동 검사와 실제 접근을 구분하고 의미 구조, 라벨, 대체 텍스트, 건너뛰기, 키보드, 읽기 순서를 확인한다.
- 12장: 상사·이해관계자의 위험한 요구에 절대 금지로 맞서기보다 그 뒤의 목적을 찾아 더 나은 대안을 내고 실제 테스트로 판단한다. 과도한 개인정보 요구와 시각적 연출이 이 원칙을 적용하는 사례다.

2판의 구체적 사이트, Flash, 이미지맵, 정확한 배치나 단어 수 같은 역사적 예시는 현재 제품의 고정 규칙으로 쓰지 않고, 현재 플랫폼 관례와 접근성 표준에 맞춰 원칙을 적용한다. 기본 뷰포트, 심각도 4단계, 발견 사항 형식, 근거 상태, 재검증 절차는 이 묶음이 정한 운영 방식이며 책의 직접 인용, 공식 점수표, 검증된 전환율 개선 공식으로 제시하지 않는다.

책의 특정 문장이나 장별 내용을 정확히 대조해 달라는 요청에는 정식으로 제공된 원문을 다시 확인하고 확인한 범위만 설명한다. 장문의 원문이나 책을 대체하는 재구성은 넣지 않는다.
