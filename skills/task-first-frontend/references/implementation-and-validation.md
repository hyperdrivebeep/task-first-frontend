# 선택된 설계의 구현과 검증

S6(구현·애프터)과 S7(보고) 단계 문서다. 산출물은 `05-after/after-<screen>-<width>.png`와 `06-report.md`이고 형식은 [work-folder.md](work-folder.md)에 있다. 게이트: `--stage 6`, `--stage 7`.

후속 구현에서 사용한다. 2026-10-13 Research Workbench 사례는 정적 시안까지였으며 아래 제품 구현·사용성 시험은 당시 수행하지 않았다.

## 구현 진입

선택과 구현 요청 범위를 확인한다. 기존 승인은 유지하되 시간이 흘렀으면 현재 코드·dirty·진행 중 작업·런타임을 다시 확인한다. 옛 SHA를 현재 main이라고 하지 않는다.

| 시안 요소 | 처리 |
| --- | --- |
| 실제 필드/행동 | 기존 consumer/API 연결 |
| 재배치/축약 | 정본을 유지하고 UI 상태만 변경 |
| 생성기가 추가한 값/메뉴 | 제거하거나 실제 계약으로 대체 |
| 기존 기능과 의미가 다른 것 | 차이를 명시하고 범위 결정 |
| 제품에 없는 핵심 기능 | 장식 버튼으로 성공을 위장하지 않음 |

제품 통합이면 기존 프레임워크/구조/검사를 사용한다. 별도 프로토타입이면 합성 데이터와 모의 동작을 표시한다. 기존 앱을 신규 템플릿으로 갈아엎지 않는다.

## 구현 순서

1. 페이지/패널 구조와 컴포넌트 재사용 지점.
2. 실제 토큰·타이포그래피·그리드, 긴 내용/좁은 화면.
3. 핵심 탐색, 입력, 상세 열기, 복귀, 초점 관리.
4. API/상태/저장/권한/취소·재개 연결.
5. 빈값/부분/실패/stale/접근 재확인 상태.
6. 선택 시안과 실제 화면 비교 및 보정.

작업에 맞게 순서를 조절한다. 파일/컴포넌트 수를 완료율로 쓰지 않는다. CSS의 책임 위치를 수정하고 반복 override를 쌓지 않는다. 요약/필터/선택은 파생 UI 상태이며 별도 사실 저장소를 만들지 않는다.

프런트엔드에서 승인·유효성·점수를 만들어 서버 계약을 우회하지 않는다. 외부 실행·권한·비용·전송은 해당 승인 범위를 따른다. 화면 검사 때문에 사용자 데이터에 시험 답안이나 연구 결과를 남기지 않는다.

## 검증 수준

| 검증 | 확인하는 것 | 증명하지 않는 것 |
| --- | --- | --- |
| 코드/계약 | 타입·상태 처리·연결 | 렌더링/사용성 |
| 화면 비교 | 선택 시안과 배치 차이 | 데이터/행동 정확성 |
| 브라우저 시나리오 | 버튼·입력·전환·저장 | 실제 사람의 이해 |
| 통합 | 정상 진입→API→저장→재열기 | 실모델 품질/운영 안정성 전체 |
| 사용자 과업 비교 | 시간·오류·이해·맥락 유지 | 작은 표본으로 보편적 개선 |
| 실기기/운영 | 명시된 기기·환경 결과 | 다른 환경 전체 |

저장소 정책에 따라 영향 범위 시험과 lint/typecheck부터 실행한다. 공통 컴포넌트/타입/경계를 바꾸면 소비자 검사를 넓힌다. 필수 전체 검사를 생략하거나 기존 실패를 PASS로 바꾸지 않는다. 동일 소스의 살아 있는 검증을 이유 없이 반복하지 않는다.

## 화면과 상호작용

선택 원본과 구현 캡처를 같은 크기·내용·상태 조건에서 함께 본다. 비율을 찌그러뜨려 맞추지 않는다. 타이포그래피·배치·간격·버튼·표/열·아이콘·색·overflow 차이를 기록하고 중요한 것을 수정한다.

과업에 필요한 항목을 선택해 확인한다. 제외 항목은 이유를 기록한다.

- 탐색/탭/메뉴, 항목 선택, 필터, 입력/제출.
- 상세→원문→복귀의 위치·초점·입력 유지.
- 빈 목록·단일·다수, 긴 한글/영문/코드·숫자.
- 로딩 중 반복 클릭, 늦은 응답, 실패/재시도, 부분 결과.
- 저장 실패 시 입력 유지, 새로고침/재열기, 회차·프로젝트 격리.
- 취소 요청/종료 확인, 재개/새 실행 구분.
- 기준 변경 후 stale/권한 재확인, 이전 데이터의 잘못된 노출.
- 키보드 순서·Enter/Escape·focus·dialog·접근 가능한 이름.
- 작은 화면/태블릿 가로·세로/확대에서 주 행동, 스크롤, 터치 대상.

## 수정 작업이면 비포·애프터 캡처 (필수)

기존 화면을 바꾸는 작업(재설계, 작은 수정, 시안의 출발점이 기존 화면인 경우)은 반드시 비포·애프터를 캡처해 보고한다.

- **비포는 바꾸기 전에** 찍는다. 나중에 옛 커밋으로 되돌려 찍었다면 그 커밋을 적는다.
- 비포와 애프터는 같은 뷰포트 크기·같은 내용·같은 상태(예: 전체화면, 같은 강의와 시각, 같은 패널 열림)로 찍는다. 크기를 바꿔 더 좋아 보이게 하지 않는다.
- 파일은 `01-before/before-<screen>-<width>.png` / `05-after/after-<screen>-<width>.png`다. 게이트가 쌍의 존재와 픽셀 크기가 같은지 검사한다.
- 대화창 보고에 비포·애프터 쌍을 나란히 표시하고, 쌍마다 무엇이 달라졌는지 한 줄로 적는다.
- 시안 단계(구현 전)에서도 비포 캡처와 시안 이미지를 같은 조건으로 나란히 보인다.

## 전후 과업 비교

`changeID`별로 기존/새 화면의 스크린샷과 실제 과업 시험 기록을 연결한다. 같은 과업·자료·상태·권한·뷰포트·기기/환경 조건을 사용하고 각 버전·실행일·조작 주체(에이전트/사람), 절차·기대/실제 결과와 순서 효과를 기록한다. 조건 차이가 있으면 비교 한계를 밝힌다. 기존 캡처나 시험이 없으면 해당 비교는 **미측정**으로 남기고 새 화면만으로 전후 효과를 추정하지 않는다.

| 항목 | 기록 |
| --- | --- |
| 정확도 | 필요한 사실/미확인 상태를 정확히 설명·처리하는가 |
| 발견성 | 주 행동과 정보를 찾는가 |
| 탐색 부담 | 실제 클릭·전환·스크롤 왕복·맥락 상실 |
| 시간 | 실측만; 추정 시간을 측정으로 쓰지 않음 |
| 실수 | 제안/승인, 현재/과거, 미대조/없음의 혼동 |
| 복구 | 오류/이탈 후 입력과 작업 복구 |

에이전트 조작은 브라우저 시험이다. 사람의 이해를 확인하지 않았다면 '초보도 사용 가능', '더 빠름', 'UX 향상 입증'이라고 하지 않는다. 정적 시안은 관찰 가능한 배치 차이까지만 평가한다.

스크린샷이나 Lighthouse 점수만으로 과업/사용성 개선을 주장하지 않는다. 효과는 실제 비교한 지표와 조건에 한정하고, 변화 없음·악화·트레이드오프도 보고한다. 사람 대상 연구는 요청과 판단 위험에 비례해 선택하며, 검증 항목별 주장/근거를 모두 채우기 위한 고비용 연구를 의무화하지 않는다.

## 마감

산출물과 미리보기를 확인한다. 저장된 캡처·파일을 읽어 보고 보고와 일치시킨다. 임시 도구는 프로젝트 정책에 따라 정리하되 최종 시안·근거를 지우지 않는다. 서버/탭 유지 여부는 사용자 요청과 도구 규칙을 따른다.

인계: 선택과 변경, 실제 검증/결과, 미실행/위험, 현재 branch/SHA/dirty, 관련 파일. 코드/배포/실모델/사람 검증을 구분한다. 공개·배포·commit/push·외부 전송은 사용자의 해당 지시가 범위를 정한다. 결과물(설계 문서, 시안, 출처 보드, 비포·애프터, 조사 보고)은 사용자가 다른 컴퓨터에서도 볼 수 있게 저장소 브랜치·PR로 올리고 링크를 보고한다. 병합은 저장소의 검토 규칙을 따른다. 보고서 `06-report.md`에는 출처 보드와 비포·애프터를 이미지로 넣고 PR 링크를 적는다.

변경별로 `changeID → 레퍼런스 기록 → 적용한 화면·파일/컴포넌트·커밋(미커밋이면 기준 SHA+dirty/diff 위치) → 전후 캡처·과업 시험 → 결과/한계`를 보고한다. 증거를 위해 커밋을 새로 만들 필요는 없다. **적용 여부**와 **효과**는 별도 필드로 두고, 검증 항목별 주장/근거는 실제 증거 범위에 한정한다. 아래 세 항목은 순차적인 완료 등급이 아닌 **독립적인 증거 축**이다. 단계를 차례로 통과하거나 다음 수준으로 올라갈 필요는 없다. 항목별 미수행·미측정을 명시한다.

| 검증 항목별 주장/근거 | 필요한 증거와 한계 |
| --- | --- |
| 적용 확인 (application verified) | 근거와 연결된 구현 위치·실제 화면 확인; 과업 성공이나 개선 효과는 미입증 |
| 과업 동작 시험 (task behavior tested) | 정상 진입에서 실제 과업의 절차·기대/실제 결과; 통과/실패를 명시하며 이 시험만으로 사람의 사용성을 입증하지 않음 |
| 사람 사용성 측정 (people usability measured) | 사람 참여자의 과업·표본·방법·조건·실측 결과; 전후 근거가 없으면 개선은 미측정, 측정 자체가 개선을 뜻하지 않음 |
