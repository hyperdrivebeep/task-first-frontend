Persona and journey notes:
- A person unable or unwilling to make a specific gesture needs another route to the same task; custom gesture discovery must not become a prerequisite for important actions.
- A new user starts with familiar gestures and visible navigation, then learns optional shortcuts in context.
- A person manipulating an object needs immediate, predictive feedback and a clear explanation when a lock or unavailable state blocks the action.
- A keyboard-and-pointer user adding occasional touch needs stable layout, reachable targets, and continued primary-input access; temporary touch expansion is conditional, not a universal resizing rule.
- A game player may need simultaneous controls; this is not a blanket recommendation to recognize multiple gestures in every interface.
- A spatial user may be seated, have limited room, have only one hand available, or become tired. Indirect input, reachable direct interaction, and simpler alternatives address different constraints.
- Standard gesture meanings are context- and host-dependent. In particular, the source assigns different double-tap actions to different devices; no single universal double-tap mapping is inferred.
- System-overlay deferral is an Apple-specific exception, not general permission to intercept system gestures. The transferable rule preserves system access and avoids collisions.
- All source tables and platform sections were read. Numeric device versions and gesture finger counts remain platform facts, not newly imposed universal thresholds.
