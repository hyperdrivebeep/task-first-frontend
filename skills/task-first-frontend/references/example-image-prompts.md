# Research Workbench 이미지 생성 프롬프트 공개 예시

2026-10-13의 세 독립 built-in ImageGen 호출에서 사용한 prompt의 제품명을 일반화한 공개 예시다. 과업·구조·내용·제약은 유지했다. 아래 날짜·수치·색·문구·레이아웃은 역사적 사례다. 새 제품에는 그대로 적용하지 말고 [design-and-ideation.md](design-and-ideation.md)의 골격을 사용한다. 결과의 가짜 부가 메타데이터와 남은 한계는 [사례 기록](case-study-and-coverage.md)에 있다.

세 호출 공통: `transparent_background=false`. 이미지 참조는 실제 로컬 파일을 `referenced_image_paths`로 제공했다. 인용한 파일명의 기준 폴더는 당시 `outputs/ui-design-example/`이다. 생성 원본/표시 번호 매핑은 사례 기록에 있다.

## 첫 번째 표시 결과

입력 이미지: `01-entry.png`, `03-evidence.png`.

```text
Create realistic production-quality UI design, one independent desktop web-app screen at 1280 x 720, NOT a collage. Direction name: "결과를 읽는 작업 공간". User is evaluating a Research Workbench redesign based on actual code, task analysis, first-party interaction research. Attached images 1 and 2 are the CURRENT Research Workbench UI to improve, not layouts to copy. Keep its Blueprint React enterprise visual language and familiar Research Workbench wordmark: dark charcoal #1c2127, panel #22272f, muted slate separators, blue #4c90f0, pale blue #8abbff, amber only for unresolved states, Inter/Pretendard/Noto Sans KR. Korean UI with crisp readable 14–16px body text, no huge empty hero, gradients, neon, dashboards metrics, card-in-card, rounded floating whole-app frame, fake scores or invented charts. The image itself IS the app viewport, no browser chrome, no slide title above app.
User task: understand the saved investigation, verify a claim against evidence, distinguish hypotheses from fact, identify next check. Choose generous reading layout with a SLIM 180px project navigation on left, primary readable report area ~700px center, compact 320px cited-source reader on right. Only 48px single top context strip. Collapse old conversation into subtle "이전 대화" control. No permanent giant chat composer: use a slim bottom "질문 또는 새 근거 추가…" bar with small "답변 한국어" control. Current display language Korean with separate display-language dropdown in top corner. Current date 2026-10-13.
Same truthful synthetic case for all concepts: project "합성 LAB-42", short display title "A 조건의 목표 미달". Small clearly visible "합성 데이터 · 실제 연구 결과 아님" note. Status strip "조사 종료 · 판단 보류" and subtitle "원인은 아직 확인되지 않았습니다." Center headline "A는 목표보다 0.15 낮습니다". Reading section "기록으로 확인한 사실": three short lines: "A 0.80 · 목표 0.95 이상 [1]", "20°C에서 3회 측정 [1]", "B는 미측정 [2]". Note these are recorded facts, not confirmed causes. Highlight the [1] citation as selected. Right source panel shows heading "근거 원문", source "language-lab.html", plain small 3-column table Condition/Quality/Repeats in Korean, row A 0.80 3 highlighted, B 미측정 0; quote "목표 품질은 0.95 이상이다." source-location text. Beneath source: "비공식 참고 · 기준 시점 내". Source section title and selected quote ABOVE metadata/filters, not buried.
Center next section "아직 모르는 것": "측정 방법·재료·반복별 결과가 필요합니다." Then "검토할 원인" with two clean unboxed rows: "온도 영향 — 미확정", "재료 영향 — 미확정". Final small amber line "반증 검색 안 함 · 가설별 근거 8개 아직 미대조". ONE primary blue CTA "가설·시험 비교", secondary text link "전체 답변". Avoid overly dense details or excessive badges. Under CTA compact contextual text "시험은 제안이며 실행에는 별도 승인이 필요합니다." Preserve not-known as not-known; do not turn hypothesis into fact.
Use spacing and typography on a flat surface, thin separators only, strong aligned baseline grid, high contrast, practical desktop UI. Design should convincingly solve information hierarchy and evidence readback, rather than advertise features. No displayed design option number.
```

## 두 번째 표시 결과

입력 이미지: `02-hypotheses.png`, `reference-palantir.png`.

```text
Create one realistic production-quality DESKTOP UI design, independent concept "가설을 비교하는 작업 공간", 1280 x 720 target viewport aspect ratio. Exactly one screen, not a collage or slide. Attached image 1 = existing Research Workbench comparison interface to improve. Attached image 2 = Palantir official Object Table interaction reference; borrow aligned comparison and selected-row emphasis, NOT its white documentation page, airline data, or brand. Maintain Research Workbench Blueprint enterprise dark design: flat #1c2127 canvas, #22272f surfaces, blue #4c90f0 accent, #8abbff selection, restrained amber for unknown state, crisp Inter/Noto Sans KR 14–16px. No neon, no gradients, no decorative charts, no giant hero, no metric tiles, no card-in-card, no unsupported scores. Korean UI. Current date 2026-10-13, no fabricated metadata timestamps or source line numbers.
User task is to compare TWO tentative causes against the same evidence and decide which test request to prepare. Break away from chat sidebar layout: collapse the global left navigation to a narrow 64px icon rail with Research Workbench mark. ONE compact top bar project "합성 LAB-42" / "A 조건의 목표 미달", display language "한국어", secondary links "자료", "이력", "대화". Main work area wide and visually organized, all comparison columns visible.
Top within main area header "가설과 시험 비교" with short amber "판단 보류 · 원인 미확정". Plain one-line observation strip "A 0.80 / 목표 0.95 이상 · 20°C · 반복 3회 · B 미측정" and a source link "근거 원문". Small visible note "합성 데이터 · 실제 연구 결과 아님". No big highlighted KPI numbers.
Central wide comparison table occupies most horizontal area. Columns: "가설", "현재 근거", "아직 필요한 것", "구분할 시험". Exactly TWO rows, with row 1 selected blue tint. Row1 title "온도 영향" subtitle "미확정", current evidence "지지 0 · 반증 미검색" and "8개 아직 미대조", needed "측정 방법 · 반복별 결과", test "재료·측정 방법 고정 → 온도만 변경". Row2 "재료 영향", same unknown evidence state, needed "재료 정보 · 반복별 결과", test "온도·측정 방법 고정 → 재료만 변경". Uncompared MUST never be green support. Under table compact note "시험 순서 동률 · 비용 모름".
Lower portion is a WIDE selected-row detail area integrated into flat page, separated by rule, not a cramped drawer. Title "선택한 시험 · 온도 비교". Two side-by-side text groups: "가설이 맞다면" -> "온도별 품질 차이가 반복됩니다."; "가설에 불리한 결과" -> "온도를 바꿔도 차이가 재현되지 않습니다." Under them short amber status "예상 결과 · 아직 시험하지 않음". Clear bottom sticky action bar: text "실행 전: 효과 선언과 담당자 승인 필요", secondary "효과 선언", ONE prominent blue button "시험 요청 준비". Small label "요청 준비는 승인·실행이 아닙니다". Do not add actual run buttons, fake complete checks, or new backend functions.
Hierarchy differentiates factual observation above table, draft causal hypotheses in rows, predicted tests below. Table is reader-friendly not spreadsheet-sized tiny text. No full chat composer competing with comparison; a small "대화로 돌아가기" text control is enough. Preserve all essential truth states. Large usable comparison area, disciplined enterprise visual design, no displayed concept number.
```

## 세 번째 표시 결과

입력 이미지: `02-hypotheses.png`, `05-history.png`.

```text
Create ONE independent production-quality desktop web app UI mockup at target 1280 x 720 aspect ratio, direction "확인할 일을 따라가는 작업 공간". Not a collage, not presentation. Input images are actual current Research Workbench screen and history screen, used for its existing brand and states, NOT their layout. Redesign based on actual task: researcher needs to identify what can be concluded and what remains necessary before a test. Visual language stays Research Workbench / Blueprint React dark enterprise: #1c2127 base, #22272f surface, #4c90f0 blue, pale #8abbff, #e7b96e amber. Readable 14–16px Korean Noto Sans KR and compact Inter. Flat surfaces, disciplined spacing, no gradients/neon/photos/hero artwork, no scores, no arbitrary success checkmarks, no card nesting. Current date 2026-10-13. Do not invent source line numbers, recorded timestamps, accounts or progress percentages.
STRUCTURALLY DISTINCT guided review layout: ONE compact 56px global top bar with Research Workbench brand at left, project dropdown "합성 LAB-42", context "A 조건의 목표 미달", right "자료", "이력", "표시 언어 한국어". NO full project tree or persistent chat composer. Under this a calm 210px left column titled "검토 목차", vertical text navigation "관측값 읽기", "근거 대조", active "가설 비교", "시험 요청 준비". These are view navigation, NOT mandatory gates, show simple thin blue active marker not numeric completion percentage or ticked steps. Bottom left muted "어느 항목이든 바로 볼 수 있습니다." and "대화로 돌아가기".
Main wide content area, comfortable central reading column width ~850. Top little amber "판단 보류 · 원인 미확정". Main task title at moderate 26px "두 가설을 무엇으로 구분할까요?" with subtitle "기록된 사실과 시험 전 예측을 나눠 확인합니다." Small visible "합성 데이터 · 실제 연구 결과 아님". A compact plain observation line under divider: "확인된 기록   A 0.80 / 목표 0.95 이상 · 20°C · 반복 3회 · B 미측정" with "근거 보기" inline blue link.
Middle is TWO paired explanatory columns on the same flat surface separated by a single vertical hairline (NOT a spreadsheet, no table outlines, no dashboard cards):
left heading "온도 영향" small status "미확정"; label "고정할 조건" text "재료와 측정 방법"; label "바꿀 조건" text "온도"; label "가설이 맞다면" text "온도별 품질 차이가 반복됩니다."
right heading "재료 영향" small status "미확정"; label "고정할 조건" text "온도와 측정 방법"; label "바꿀 조건" text "재료"; label "가설이 맞다면" text "재료별 품질 차이가 반복됩니다."
A modest single note below comparisons: "두 가설 모두 반증 미검색 · 근거 8개 아직 미대조". Then section "지금 더 필요한 자료" with a short actual list "측정 방법 / 재료 정보 / 반복별 결과" as simple inline text. Note "없는 결과를 추정하지 않습니다." Do not claim sources cause hypotheses. Do not include checkboxes falsely implying data verified.
Bottom dedicated action area on flat surface: secondary text button "근거 대조로 돌아가기" on left, single primary blue CTA "시험 조건 검토" right. Below small contextual instruction "시험 요청 준비 후에도 효과 선언과 담당자 승인이 필요합니다." This is a viewing/navigation step, not actual execution or granting approval. Footer very compact "전체 답변" and "질문 추가" links keep full content accessible but do not compete.
Clear uncluttered beginner-friendly information hierarchy yet adult scientific workbench not learning gamification. Fit all above within frame, avoid dense repeated disclaimer panels, preserve truthful uncertainty. No displayed concept number.
```
